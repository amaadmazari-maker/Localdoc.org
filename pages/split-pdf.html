Technical Architecture: Selective Object Subgraph Cloning & Mark-and-Sweep Extraction

In accordance with the ISO 32000-1 format specification, PDF documents structure pages as terminal leaf nodes inside a balanced B-tree. You cannot slice or split a PDF by severing raw byte offsets without invalidating the document catalog and cross-reference table. LocalDoc performs deterministic directed graph surgery directly within browser memory:

  • Page Node Traversal & Root Re-indexing: When you specify target ranges (e.g., pages 12–15 or chunk intervals of 5 pages), LocalDoc descends through intermediate /Pages parent nodes, locates the corresponding /Type /Page leaf dictionaries, and synthesizes a new root /Catalog and /Pages collection with an updated /Count property.
  • Deep Dependency Graph Traversal & Asset Pruning: To prevent extracted 2-page chapters from ballooning to the size of the 500-page original book, LocalDoc executes a mark-and-sweep garbage collection pass. Starting from each selected page's /Contents streams and /Resources dictionary (including /Font, /XObject, /ExtGState, and /ColorSpace), the engine marks all reachable indirect objects. Unreferenced font subsets, high-res images, and CAD diagrams belonging to discarded pages are excluded from the output.
  • Contiguous XRef Table & Trailer Reconstruction: A new, clean cross-reference table (xref) or compressed object stream (/ObjStm) is generated with sequential, 1-indexed object IDs and precise byte offsets. This ensures the output PDF adheres strictly to ISO standards, opening cleanly in Adobe Acrobat, PDF.js, Preview, and mobile PDF engines.
  • In-Memory JSZip Burst Streaming: When 'Burst All Pages' or 'Split in Chunks' mode is triggered, each extracted segment is packaged into an independent, valid PDF container and streamed into an in-memory PKZip archive using client-side DEFLATE compression. The resulting ZIP file is generated in browser memory, enabling a 1-click bundle download without multiple browser download prompts.
  • Ephemeral Memory Lifecycle: Processing multi-hundred page documents inside client RAM is safeguarded by strict memory disposal. Once the extracted PDF or ZIP Blob URL is emitted, intermediate canvas contexts and byte arrays are unreferenced for immediate V8 engine garbage collection, ensuring zero data leakage and optimal mobile browser stability.

Frequently Asked Questions About Splitting PDFs

How do I split a PDF into individual pages and download all in 1 click?

Upload your document, keep the default "Individual Pages (1-Click ZIP)" tab selected, and click "Split into Individual Pages". LocalDoc extracts every page into an individual PDF file and generates a convenient 1-Click ZIP download, along with direct download buttons for each individual page.

How does splitting in pairs or 2–10 page chunks work?

Switch to the "Split in Pairs / Chunks" tab. Choose a preset pill (2 for 2-page pairs, 3 for triplets, 5 for 5-page chapters, or up to 10 pages per file max). LocalDoc automatically calculates the segment boundaries and packages the resulting multi-page PDFs into a ZIP archive.

Can I delete or exclude unwanted pages before splitting?

Yes. Every thumbnail card has a dedicated delete button (✕). Clicking it marks the card as excluded, updates the active page count, and recalculates split chunk boundaries in real time. Click "↺ Restore All" if you ever want to re-include them.

Can I extract non-consecutive pages like pages 2, 5, and 11 into one PDF?

Yes. Switch to "Extract to Single PDF", click on thumbnails #2, #5, and #11, or enter "2, 5, 11" into the page range field. LocalDoc will combine only those three pages into a single cohesive PDF.

Will splitting a PDF reduce visual quality or text sharpness?

No. Splitting is a 100% lossless structural operation. The original vector fonts, high-resolution raster images, and mathematical layout coordinates are cloned byte-for-byte into the new document container.

Syntax Validation & Large Document Handling

Page Number Validation: Page numbers must be within the actual page count of the document. If your file has 20 pages and you enter "15-25", LocalDoc will automatically clamp the upper bound to page 20.

Bursting 100+ Page Documents on Mobile: Generating over 100 separate PDF files and compressing them into a ZIP archive creates substantial memory allocation. If using an older smartphone, extract chapters in batches of 20 to 30 pages to prevent tab memory refreshes.
