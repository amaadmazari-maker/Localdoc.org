Technical Architecture: Multi-Engine Client-Side Document Parsing & Sandboxing

Traditional web-based document viewers require transmitting your confidential contracts, medical scans, and company spreadsheets to remote cloud servers (such as Google Docs Viewer or Microsoft Office Online), where documents are cached and processed on third-party server farms. LocalDoc embeds specialized, sandboxed client-side parsers directly into your browser runtime:

Mozilla PDF.js Vector Engine & Font Decoders

PDF documents are parsed using Mozilla's open-source PDF.js engine. Raw byte streams are unpacked into indirect object graphs, resolving cross-reference (xref) tables, embedded CMap character tables, and TrueType / CFF font glyph outlines. Vector paths and typography are rasterized onto an HTML5 Canvas scaled to your screen's exact hardware device pixel ratio (window.devicePixelRatio), ensuring crystal-clear sharpness on high-DPI retina screens.

Mammoth.js DOCX Semantic Compilation

Microsoft Word .docx archives are uncompressed in memory using pure JavaScript PKZip decoders. The engine parses the internal word/document.xml OpenXML package, mapping runs (<w:r>), paragraph properties (<w:pPr>), tables (<w:tbl>), and numbering hierarchies into sanitized semantic HTML5 elements (<p>, <h1>, <table>) without executing untrusted external scripts.

SheetJS In-Memory Spreadsheet Engine

Excel workbooks (.xlsx, .xls, and .csv) are parsed cell-by-cell into a structured memory matrix. LocalDoc constructs dynamic sheet tabs matching the original workbook's sheet hierarchy, supporting thousands of rows with zero latency. Number format masks, accounting currency symbols, and date serial numbers are correctly formatted for instant viewing.

Page Virtualization & Canvas Memory Reclamation

To prevent browser memory bloat when viewing 500+ page technical manuals or large blueprints, LocalDoc implements viewport page virtualization. Only visible and adjacent pages are rendered into active memory. When pages scroll out of view, canvas memory buffers are wiped (canvas.width = 0; canvas.height = 0) and temporary blob URLs are immediately revoked via URL.revokeObjectURL(), keeping browser heap usage strictly bounded.

DOM Containment & XSS Sandboxing

All rendered document markup is isolated using strict CSS layout containment (contain: content) and rigorous DOM sanitization. Inline script execution is blocked, preventing malicious macros, embedded tracking pixels, or cross-site scripting (XSS) vectors often present in weaponized corporate attachments.

Zero Cloud Transmissions & PWA Offline Cache

Every parser runs entirely within local browser closures. After your initial page visit, our Progressive Web App (PWA) service worker caches all parser engines locally. You can open and inspect confidential documents on an airplane, in high-security facilities, or during subway commutes with zero cellular or Wi-Fi connectivity.

Common Practical Questions & Technical Troubleshooting

Direct answers to common user questions regarding file compatibility and viewing performance:

Can I open password-protected PDF or Word documents?

If you open an encrypted PDF, the viewer will prompt you to enter the document password directly in your browser. The decryption key is processed locally using standard AES-256 routines—your password is never transmitted across the network.

Why is LocalDoc safer for confidential contracts and medical records?

Traditional "free online viewers" upload your files to remote cloud servers to convert them into HTML images, creating permanent server logs and exposing trade secrets. LocalDoc executes 100% within your device's browser memory (RAM). When you close the tab, the document ceases to exist anywhere in memory.

Can I use LocalDoc to read documents without an internet connection?

Yes. Once you load LocalDoc once, our service worker caches the viewer engines locally. You can open files on a plane, subway, or in remote areas with zero Wi-Fi or cellular connection.

How does LocalDoc display complex multi-sheet Excel spreadsheets?

When you load a Microsoft Excel .xlsx workbook, LocalDoc generates a bottom tab bar listing every sheet in the workbook (e.g., "Summary", "Q1 Budget", "Data"). Clicking any tab dynamically renders that sheet's data into clean tabular format with formatted cell values.

Does opening large PDF textbooks consume excessive device memory?

No. LocalDoc uses on-demand page virtualization via Mozilla PDF.js. Only currently viewed pages are rasterized into canvas memory, allowing you to smoothly scroll through 500+ page technical manuals and textbooks without crashing mobile browser tabs.

Can I select and copy text from documents opened in this viewer?

Yes. For Word (.docx), Excel (.xlsx), and text documents, content is rendered as native HTML text, allowing normal mouse selection and clipboard copying. For vector PDFs, text glyphs can be selected directly across rendered pages.
