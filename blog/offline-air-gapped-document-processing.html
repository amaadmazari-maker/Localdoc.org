Why Air-Gapping Matters

In high-security environments—including defense, healthcare (HIPAA), banking, and legal counsel—connecting to cloud conversion tools is strictly prohibited by security policies. LocalDoc's Progressive Web App (PWA) architecture enables full document manipulation with physical network cables disconnected.

1. How to Enable 100% Offline Mode

  1. Visit localdoc.org once on any modern browser (Chrome, Edge, Firefox, Safari).
  2. Our Service Worker automatically pre-caches all 20 tool engines and WebAssembly binaries in your browser storage.
  3. Disconnect your Wi-Fi or unplug your Ethernet cable.
  4. You can now convert, merge, split, compress, sign, and OCR documents indefinitely with zero internet access.

3. The Threat Landscape of Cloud Document Ingestion

Why do compliance frameworks like HIPAA, GDPR, ISO 27001, and SOC 2 view cloud document converters with extreme skepticism? When an employee uploads an unredacted document to a third-party server, the enterprise incurs four immediate threat vectors:

  • Unauthorized Sub-Processor Exposure: Most freemium cloud PDF utilities do not host their own servers; they forward payloads through multi-tenant cloud storage buckets or third-party OCR APIs located in jurisdictions outside national regulatory boundaries.
  • Residual Data Retention: Even when a service promises "files deleted after 1 hour," transient cache layers, crash dump logs, and automated backup snapshots often retain file fragments for months.
  • AI Model Scraping: Without transparent contractual indemnification, uploaded proprietary documents and intellectual property may be ingested into training corpora for large language models.
  • Man-in-the-Middle (MitM) & DNS Hijacking: Network transit introduces vulnerability to SSL inspection proxies, compromised Wi-Fi networks, and rogue certificate authorities.

4. Progressive Web App (PWA) Service Worker Mechanics

LocalDoc achieves permanent offline capability using an advanced Cache-First Service Worker architecture registered via the sw.js controller script. When you navigate to LocalDoc for the first time:

  1. The Service Worker intercepts all network requests for core JavaScript modules, WebAssembly binaries (pdf-lib, tesseract), and CSS stylesheets.
  2. Assets are stored inside the browser's persistent CacheStorage API partition.
  3. Upon subsequent visits, the Service Worker serves assets directly from local storage with a 0ms latency network bypass.
  4. Even if your operating system has no network adapter active, the application loads instantaneously as a native standalone desktop or mobile app.

5. Enterprise Air-Gapped Verification Protocol

If your organization requires formal verification before clearing LocalDoc for internal staff use, your security engineering team can perform this definitive audit:

  1. Install LocalDoc as a PWA by clicking Install LocalDoc in the address bar or browser menu.
  2. Physically isolate the test machine: unplug Ethernet cabling and disable all Wi-Fi and Bluetooth radios.
  3. Launch LocalDoc from your desktop or application launcher.
  4. Open an enterprise document containing synthetic PII (Personally Identifiable Information) and perform multi-page compression, merging, and cryptographic signing.
  5. Verify through local network packet capture tools (such as Wireshark) that 0 network packets were generated during the entire lifecycle.

6. Frequently Asked Questions (FAQ)

Will LocalDoc continue to work if I restart my computer while offline?

Yes. Once the PWA is installed or cached, the browser stores the compiled assets in permanent disk cache. You can shut down, restart, and launch LocalDoc in the middle of a flight without internet access.

Do offline tools have file size limits?

The only limit is your device's available physical RAM. On modern laptops with 8GB or 16GB of RAM, LocalDoc can effortlessly process PDFs containing hundreds of pages and hundreds of megabytes without stuttering.

How are updates delivered if I use the tool offline?

Whenever your device reconnects to the internet, the Service Worker silently checks for updated script revisions in the background, updates the local cache, and activates new features seamlessly on your next launch.
