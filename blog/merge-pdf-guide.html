1. Why Merging PDFs Is Not "Gluing Files Together"

In formats like plain text or MP3 audio, combining two files is as simple as byte concatenation (appending File B to the end of File A). In the Portable Document Format (PDF), doing so produces immediate file corruption.

A PDF file is a randomly-accessed graph structure. At the very tail of every PDF file sits a critical data structure: the File Trailer, which contains the exact byte offset of the Cross-Reference (XRef) Table:

trailer
<< /Size 48 /Root 1 0 R /Info 2 0 R >>
startxref
148924
%%EOF

When a PDF viewer opens a file, it does not read from top to bottom. It jumps immediately to the startxref pointer, reads the byte offset table, and uses indirect pointers (e.g. 12 0 R) to locate pages, fonts, and images scattered across the file. If two files are concatenated naively, the secondary file trailer is ignored, and only the first document renders.

2. The Mathematics of XRef Remapping & Object Clashes

Every element inside a PDF—a page description, a TrueType font descriptor, an embedded image, or a metadata stream—is assigned an Indirect Object Identifier consisting of an object number and a generation number (e.g., 14 0 obj).

When combining Document 1 and Document 2, an immediate collision occurs: both documents almost certainly contain an object named 4 0 obj. In Document 1, object 4 might be the Helvetica font definition; in Document 2, object 4 might be a company logo.

LocalDoc’s WebAssembly core executes an algebraic transformation on the incoming object graphs:

$$ ext{NewID}(O_B) = O_B + max( ext{ID}(O_A)) + 1$$

Every indirect reference in content streams and dictionary structures is re-wired to point to its newly allocated global slot, guaranteeing zero collision and 100% font rendering fidelity.

3. Catalog Tree Synthesis & The /Pages Node Hierarchy

In ISO 32000-1, pages do not exist in a flat array. They are organized as a balanced B-tree of /Pages node dictionaries terminating in individual /Page leaf dictionaries:

2 0 obj
<< /Type /Pages /Kids [3 0 R 4 0 R 5 0 R] /Count 3 >>
endobj

When merging documents, LocalDoc does not merely graft one tree onto another. It synthesizes a new root /Pages collection, calculates the cumulative /Count, updates the /Parent pointers of every incoming page leaf, and ensures that shared resource dictionaries (such as color spaces and standard font encodings) are unified.

4. Preserving Mixed Page Dimensions & Rotation Flags

A frequent enterprise requirement is compiling a binder that includes portrait contract pages ($8.5 imes 11 ext{ in}$), landscape accounting ledgers ($11 imes 17 ext{ in}$ or $8.5 imes 14 ext{ in}$), and ISO A4 sheets.

Flawed PDF tools force a single uniform dimension across all merged pages, either cutting off spreadsheet columns or letterboxing text with massive white margins. LocalDoc inspects each page's /MediaBox, /CropBox, and /Rotate dictionary keys independently:

5. Bookmark & Hyperlink Synthesis Across Documents

When preparing legal discovery binders, board packets, or academic theses, interactive bookmarks (the /Outlines dictionary hierarchy) are essential for rapid navigation.

Most basic mergers discard document outlines completely, forcing users to manually recreate bookmarks. LocalDoc traverses each source document's outline tree, shifts destination page indices by the cumulative preceding page count:

$$ ext{TargetPage}_{ ext{Merged}} = ext{TargetPage}_{ ext{Original}} + sum_{i=1}^{k-1} ext{PageCount}(D_i)$$

This ensures that clicking "Exhibit B - Audit Report" in your PDF reader's sidebar jumps precisely to page 43 of the combined document, rather than page 1.

9. Frequently Asked Questions (FAQ)

Can I merge PDF files with different page sizes and orientations?

Yes. PDF files define page dimensions on a per-page basis using the /MediaBox and /Rotate dictionary keys. LocalDoc preserves each source page's native dimensions, allowing you to combine portrait letter documents with landscape spreadsheet exhibits seamlessly.

Does merging PDFs combine their bookmarks and interactive table of contents?

Yes. LocalDoc's merger synthesizes the /Outlines dictionary tree, appending each document's bookmark hierarchy under its respective file section, so navigation links remain fully functional in Adobe Acrobat and browser viewers.

Why do some online mergers corrupt fonts or images when combining files?

Naive mergers fail to resolve indirect object ID collisions. If File A and File B both define object 4 0 obj as a font descriptor, a flawed merger overwrites one with the other, rendering text as illegible symbols. LocalDoc re-maps every object ID into a new global namespace.

Is there a limit on how many files or pages I can merge in LocalDoc?

Because LocalDoc operates 100% in local browser memory without server upload bandwidth constraints, you can merge dozens of files and hundreds of pages, limited only by your computer's available RAM.
